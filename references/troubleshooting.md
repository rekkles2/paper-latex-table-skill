# Validation and recovery

Static validator exits: 0=supported static checks passed; 1=detected failure; 2=unsupported structure needs review. Neither 0 nor a PDF proves correctness. Linter covers comments, brace/environment balance, duplicate labels, references requiring document context, basic l/c/r/S arity, and multicolumn spans; it does not expand macros, solve multirow coverage, parse custom column types or interpret arbitrary TeX. Nested tabular, macro-defined rows and custom preambles require compilation and manual review. Inferred packages are suggestions, not complete dependency validation. Only explicit data contracts support deterministic numerical validation.

Compiler: fresh output directory for each run; captures two-pass stdout/stderr, engine log, PDF and report. Passed requires exit 0, PDF and no fatal log errors. Undefined references, missing glyphs, overfull/underfull boxes and float warnings remain review findings. Actual paper layout may differ from the generic article wrapper. Unknown TeX is executable input: use an OS sandbox for untrusted downloaded code; no-shell-escape alone does not isolate filesystem access. No package auto-installation or engine/provider retries.

Render with inspect_render.py then open every relevant PNG with an image viewer/tool. Examine margins, header/rule intersections, merged cells, glyphs, bold/underline, whitespace and caption separation at publication size. Record reviewed page/PDF hashes and defects; rendering leaves visual_review=pending until an actual reviewer records the result. A log with no warnings does not detect all clipping or small fonts. Poppler absent -> unavailable, never a visual pass.
