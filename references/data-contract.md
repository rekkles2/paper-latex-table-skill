# Generated tables and refinement ledgers

Use `assets/templates/benchmark.json` as the smallest runnable contract. JSON schema version 1; Python runtime validates the supported subset with `check_spec`. Duplicate JSON keys and nonstandard NaN/Infinity constants are rejected at loading, rather than silently overwriting or accepting data. Invalid or unsupported shapes raise an error rather than silently dropping data. This is not an arbitrary LaTeX serialization schema.

- `columns`: unique `id`, plain-text `label`, explicit `direction` (`higher`, `lower`, `none`), optional `unit`, `header_group`, `kind` (`number` default or `text`). Identically named header groups must be contiguous. Only one grouped-header layer is automated. Deeper headers/multirow are agent-authored LaTeX using the same data ledger.
- `rows`: unique `id`, plain-text `label`, `group` (default `all`), `eligible` (default true), and `values` with exactly the column IDs. Comparison groups must represent the same supervision, test split and evaluation protocol. Eligibility exclusions are user-defined.
- Numeric values are strings (`"82.00"`, `"-1.2e-3"`); no JSON floats, rounding, percentage conversion or implicit unit conversion. `null` is an explicitly missing value and prints `--`. `"0.0"` is a real, rankable value. Preserve richer missing reasons in the manual ledger or descriptive text; the generator does not infer them from strings like `-`.
- Rich values: `{"mean":"82.00","std":"0.20"}` or `{"mean":"82.00","ci":["81.60","82.40"]}`. Specify `rank_on: "mean"` on any ranked rich column. Statistical uncertainty is not a significance test.
- Text values require `kind: "text"` and `direction: "none"`. Dates, parameter strings, original Rank columns and model sizes normally belong here.
- `float`: `table` or `table*`. `alignment`: `center` (default) or `decimal` for scalar numeric columns only. Decimal mode uses siunitx S; highlighted/missing cells use an explicit centered multicolumn escape, so those cells are not decimal-aligned. For all-row decimal alignment with bold/underlining, author tested siunitx-compatible markup manually.
- Caption, label and row_header are optional; labels allow letters, numbers, `:_.-`. All plain text is escaped. Inputs are data, not TeX commands.

Ranking chooses the best and second distinct score in each `row.group`, with exact Decimal equality. All ties receive the same mark. One distinct score gives best only. This policy computes highlighting, not a displayed ordinal Rank column. Do not recompute an existing ordinal rank under this policy. Do not interpret an error or latency direction without units/protocol. Parameter counts remain unranked unless the user explicitly defines that objective.

`generate_table.py` writes a `.ledger.json` sidecar binding original JSON and rendered TeX hashes, including supplied caption, header and presentation fields. `validate_table.py --spec` requires exact deterministic renderer output; arbitrary stylistic edits fail this check and need manual mapping. `tablelib.compare` compares keyed JSON contracts and catches movement between models/datasets, changed units/eligibility, missing IDs, precision, caption and row-header changes. Labels, float width and alignment may intentionally change during refinement; use `include_presentation=True` to protect those too. It is not a parser that extracts data from arbitrary TeX.

## Existing LaTeX refinement

Keep the original file byte-for-byte. Before editing, create a JSON ledger with `source_sha256`, `cells`, and a separate `caption_claims` list. Each cell record has: `row_id`, `column_id`, `raw_before`, `raw_after`, `value_strings`, `unit`, `metric_direction`, `comparison_group`, `missing_reason`, and `delta` (null or `{baseline_cell, mode, value_string}`). Include uncertainty components and superscripts. Record a raw snippet per cell; never use a bag of numbers as the oracle. Keep unchanged source bytes for passthrough cells. For changed markup, visually check that each raw_after snippet still represents the same cell and all exact value strings. Cite the source location. This is an agent-reviewed format, not an automated extraction capability.

For deltas use `tablelib.delta(new, baseline, mode)`: `absolute` or `percentage_points` returns new minus baseline; `relative_percent` returns 100*(new-baseline)/baseline and rejects zero baseline. Inputs must already use compatible units; percentage points requires values on a 0..100 scale, not fractions. Negative baselines and averaged ratios need a stated scientific interpretation. Do not infer the baseline from a macro name, row order or arrows. Never silently recalculate an existing average. Subtraction preserves long input precision; relative division uses at least 50 Decimal significant digits and may have a non-terminating expansion. Formatting a derived result requires a stated, user-approved rounding policy; the helper does not format or insert deltas into tables automatically.
