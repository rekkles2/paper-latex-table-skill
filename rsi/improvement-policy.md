# Controlled improvement

RSI means updating verified cases, instructions and helper code from observed failures, not model-weight training. Routine successful generation does not automatically become a stable reference. Propose the smallest fix with the failing case, before/after evidence and regression coverage. Keep unreviewed candidates separate, including any rights-unknown examples. Do not rewrite stable files during evaluation.

Create a complete candidate skill copy outside the stable folder. `rsi.py propose CANDIDATE --state STATE --reason TEXT --case ID` snapshots the baseline and creates a hash-addressed proposal. STATE must be outside both the candidate and stable skill trees; otherwise a baseline snapshot could include its own history. `evaluate FOLDER` runs the maintained baseline regression harness against candidate modules and binds candidate/baseline/test-log hashes. Existing records cannot be overwritten through this CLI. Evaluation executes Python; use only authorized local candidates.

After actual compilation and visual review, save a JSON review with `candidate_hash`, `status: "passed"`, `reviewer`, and nonempty `artifacts: [{path, sha256}]` relative to that review. Include compile reports and inspected PDFs/PNGs; the record is a reviewer attestation, not automated vision proof. `accept FOLDER --approve-by NAME --approval EXPLICIT_USER_APPROVAL --visual-review REVIEW.json` verifies all bindings and records accepted_for_manual_integration. The operator must actually have explicit user approval; naming an approver is not itself permission. No script copies accepted candidates into stable. Integrate only after reviewing the diff; rerun checks and save the accepted hash. Manual rejection is an append-only decision note; pending/failed proposals remain preserved.

Rollback: use proposal baseline.zip to inspect and restore only the intended files after checking for newer user changes, or use repository commits after the user initializes version control. Snapshots are local/private by default. A baseline ZIP is not an instruction to overwrite current work. Acceptance and new case promotion must include separate numerical, compilation, visual and rights evidence. Keep histories outside the distributable skill and public export.
